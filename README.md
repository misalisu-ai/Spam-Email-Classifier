# Intelligent Multi-Model Spam Email Classifier

## 📌 Project Overview
Emails are the backbone of modern communication, but they also bring a constant stream of spam, marketing clutter, and phishing links. Filtering out these junk messages isn't just about keeping an inbox clean; it is a critical security step to protect personal data and stop cyber attacks.

This project introduces an automated machine learning and deep learning system that scans text strings and labels them as either **"Ham"** (safe, normal email) or **"Spam"** (unwanted or harmful email). Unlike old-school filters relying on hardcoded rules, our system learns predictive word patterns directly from the underlying text data.

## 🚀 Key Features
*   **Dual-Pipeline Architecture:** Implements and compares a lightweight traditional statistical model and a modern deep learning neural network side-by-side.
*   **Interactive Web Dashboard:** Built using **Streamlit** to offer live parallel model prediction outputs and confidence panels from a single text input field.
*   **Production-Ready Precautions:** Includes structural adjustments like `EarlyStopping` callbacks to prevent overfitting and stratified splitting to combat class imbalance.

---

## 📊 Dataset & Preprocessing
*   **Source:** Public Kaggle repository curated by Y. Oswal (2022) consisting of 5,728 raw email messages.
*   **Class Imbalance:** 4,360 Ham (76.5%) and 1,335 Spam (23.5%). 
*   **Cleaning Process:** Verified null entries, removed 33 identical duplicate rows to prevent data leakage (leaving 5,695 clean rows), and intentionally retained long text sequences to mimic real-world email behavior.
*   **Vectorization:** Text was normalized to lowercase, stripped of English stop-words, and tokenized using **TF-IDF** (Term Frequency-Inverse Document Frequency) with a fixed vocabulary cap of **3,000 features**.

---

## 🏗️ Modeling Strategy

### 1. Model 1: Multinomial Naive Bayes (Baseline Control)
*   A traditional, fast, and lightweight statistical model built using Scikit-Learn.
*   **Hyperparameters:** Configured with standard Laplace smoothing (`alpha=1.0`) to avoid zero-probability calculation drops on unseen test words.

### 2. Model 2: Multi-Layer Perceptron (Deep Learning)
*   A sequential neural network built using **TensorFlow Keras** to capture complex, non-linear word combinations.
*   **Architecture Hierarchy:**
    *   **Input Layer:** 3,000 nodes (matching the TF-IDF dimensions).
    *   **Hidden Layer 1:** 128 fully connected neurons with `ReLU` activation.
    *   **Regularization:** `Dropout (0.5)` to aggressively combat overfitting.
    *   **Hidden Layer 2:** 64 compressed neurons with `ReLU` activation.
    *   **Output Layer:** 1 node with `Sigmoid` activation to yield final probabilities.
*   **Compilation:** Optimized using the `Adam` optimizer, `binary_crossentropy` loss, and an `EarlyStopping(patience=2)` monitor.

The final models were tested against a locked-away 20% validation pool (1,139 total emails: 865 Ham / 274 Spam).

### 🔍 Real-World Security Interpretation
While both setups reached incredible metrics, the **Neural Network** dropped missed spams (False Hams) down to just **2 messages** (compared to 11 in Naive Bayes). Minimizing False Hams is critical for email security, as it stops dangerous phishing strings and malicious scams from ever landing in a user's primary inbox.

## 🛠️ Infrastructure & Deployment Lessons
*   **Streamlit Cloud Python Runtime Crash:** Encountered deployment issues when Streamlit defaulted to Python 3.14 (unsupported by stable TensorFlow binaries). This was resolved by forcing a stable Python 3.11 container environment via `runtime.txt` and using `tensorflow-cpu`.
*   **Keras Matrix Shape Bug:** Fixed a web UI matrix dimension anomaly by updating Streamlit's interface code to explicitly slice into the nested array outputs (`prediction[0][0]`) generated by Keras.
